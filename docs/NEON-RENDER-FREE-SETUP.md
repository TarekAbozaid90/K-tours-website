# دليل تشغيل K-tours بالخطة المجانية — Render + Neon

## ليه Neon؟

لو استخدمنا Render PostgreSQL المجاني، قاعدة البيانات بتنتهي بعد 30 يوم. ولو حفظنا الصور أو SQLite في ملفات Render المجانية، الملفات بتضيع عند إعادة التشغيل أو إعادة النشر أو دخول الخدمة في وضع السكون. لذلك النسخة دي بتستخدم Render Free لاستضافة التطبيق وNeon Free لقاعدة PostgreSQL، وبتحفظ الصور نفسها داخل PostgreSQL كـ BYTEA بدل قرص Render مدفوع. Neon خارج Render، وده التنازل المطلوب علشان نحصل على قاعدة دائمة مجانية.

## 1) إنشاء قاعدة Neon مجانية

1. افتح <https://console.neon.tech/> وسجّل الدخول.
2. اختار Create project.
3. اختار Free plan.
4. اختار Region قريبة من Render؛ Frankfurt / `eu-central-1` اختيار مناسب لو متاح.
5. افتح Connect.
6. اختار قاعدة البيانات والـ role الافتراضيين، وانسخ Pooled connection string (غالبًا اسم المضيف فيه `-pooler`).
7. اتأكد إن الرابط فيه `sslmode=require`، واحتفظ به سرًا.

الخطة المجانية الحالية حسب وثائق Neon: 1GB PostgreSQL لكل مشروع، 100 CU-hours شهريًا لكل مشروع، و5GB نقل بيانات عام، مع إيقاف compute بعد 5 دقائق خمول. راجع صفحة الخطط قبل الإنشاء لأن الحدود ممكن تتغير.

## 2) رفع الموقع على GitHub

1. حمّل وافتح ZIP.
2. ادخل مجلد `k-tours-site`.
3. ارفع كل محتوياته إلى جذر Repository جديد في GitHub، وليس المجلد الأب.
4. تأكد إن `render.yaml` و`package.json` و`server.js` ظاهرين في الجذر.
5. لا ترفع ملف `.env` ولا رابط Neon ولا كلمة المرور.

## 3) إنشاء Render Free Web Service

1. افتح <https://dashboard.render.com/>.
2. اضغط New + ثم Blueprint.
3. اربط Repository الجديد.
4. Render هيقرأ `render.yaml` ويجهّز خدمة Node واحدة باسم `k-tours-fullstack` على Free.
5. عند طلب القيم اليدوية أدخل:
   - `DATABASE_URL`: رابط Neon pooled connection string.
   - `ADMIN_USERNAME`: اسم المدير (مثل `admin`).
   - `ADMIN_PASSWORD`: كلمة مرور فريدة لا تقل عن 12 حرفًا.
6. Render هيولّد تلقائيًا `SESSION_SECRET` و`VISITOR_IP_ENCRYPTION_KEY`. سيبهم كما هم.
7. اضغط Apply / Create Resources وانتظر اكتمال Build & Deploy.

**مهم:** Blueprint لا ينشئ Render PostgreSQL ولا Persistent Disk. ده مقصود لتجنب أي مورد مدفوع أو قاعدة مجانية تنتهي بعد 30 يومًا.

## 4) اختبار الاتصال

افتح رابط الموقع ثم أضف `/api/health`، مثال:

`https://your-service.onrender.com/api/health`

المتوقع:

```json
{
  "ok": true,
  "database": "connected",
  "visitorBook": true,
  "imageStorage": "postgresql"
}
```

أول تشغيل ينشئ الجداول تلقائيًا. لو ظهر database unavailable، راجع `DATABASE_URL` في Render Environment وتأكد إنك استخدمت الرابط pooled واحتفظت بـ `sslmode=require`.

## 5) بيانات المدير

لتغيير اسم المستخدم أو كلمة المرور: Render → k-tours-fullstack → Environment. عدّل `ADMIN_USERNAME` أو `ADMIN_PASSWORD` ثم Save and Deploy. استخدم كلمة مرور فريدة بطول 12 حرفًا على الأقل. كل الجلسات القديمة هتنتهي بعد تغيير بيانات الدخول.

## 6) دفتر الزوار

- أول مرة، الزائر هيشوف إشعار خصوصية بالعربي أو الإنجليزي.
- التسجيل لا يبدأ إلا بعد الضغط على Allow / موافق. اختيار No thanks / لا شكرًا لا يمنع استخدام الموقع ولا يسجل زيارة في قاعدة K-tours.
- لو وافق، السيرفر يسجل IP مشفر، والمدينة/الدولة بشكل تقريبي، وفئة الجهاز، والمتصفح ونظام التشغيل، والصفحة ووقت الزيارة. نفس المتصفح يتسجل مرة واحدة كل 24 ساعة لتقليل التكرار.
- تحديد المدينة يتم من خلال ipwho.is بعد الموافقة فقط. خدمة ipwho.is المجانية لا تحتاج مفتاح API وتعلن حد 1000 طلب يوميًا لكل عنوان IP صادر من الخادم الذي يستدعي الخدمة. يحتفظ التطبيق بنتيجة كل IP في الذاكرة لمدة 24 ساعة لتقليل الطلبات المتكررة.
- عنوان IP مشفر في قاعدة البيانات، ولا يظهر كاملًا إلا داخل لوحة الإدارة بعد تسجيل الدخول.
- البيانات تتمسح تلقائيًا بعد 30 يومًا. لوحة التحكم تسمح بتحديث الدفتر ومسح جميع سجلاته.
- رابط Privacy choices في تذييل الموقع يسمح بسحب الموافقة؛ الموقع يحاول حذف السجلات المرتبطة بنفس المتصفح.
- المدينة تقديرية وليست عنوانًا دقيقًا، وقد تختلف مع VPN أو شبكات المحمول.

### تنبيه قانوني

عنوان IP ومعرّفات الإنترنت قد تدخل ضمن البيانات الشخصية بموجب قانون حماية البيانات الشخصية المصري رقم 151 لسنة 2020. إرشادات مركز حماية البيانات تؤكد أهمية الموافقة الواضحة والمحددة والاحتفاظ بسجلها. ده إعداد تقني للشفافية وتقليل البيانات، وليس استشارة قانونية أو ضمان امتثال. راجع متخصصًا مصريًا بشأن الأساس القانوني والتراخيص/التصاريح وأي نقل بيانات خارج مصر قبل الإطلاق العام.

## 7) الصور والمساحة

لتجنب القرص المدفوع، صور معرض الإدارة وصور تقييمات العملاء بتتحفظ داخل Neon في `BYTEA`. الحدود الحالية: صورة واحدة للمعرض حتى 3MB، وتقييم واحد حتى صورتين 3MB لكل صورة. التطبيق يوقف رفع الصور تلقائيًا عند وصول إجمالي أحجام الصور المرفوعة إلى نحو 650MB، علشان يسيب مساحة احتياطية من حد Neon المجاني البالغ 1GB للجداول والجلسات وسجلات الزوار. اضغط الصور قبل رفعها واحذف الصور غير اللازمة.

## 8) تكبير الصور وتفاصيلها

اضغط على صورة الـHero في أعلى الصفحة أو أي صورة داخل الصفحة الرئيسية أو صور التقييمات المعتمدة. وفي لوحة الإدارة اضغط على صور المعرض أو صور التقييمات المعلقة لفتح معاينة أكبر. هتظهر نافذة تكبير فيها العنوان والوصف، ورابط لفتح الصورة الأصلية، وأسهم للتنقل بين الصور. اضغط Esc أو زر الإغلاق للخروج.

## 9) اختبار الإطلاق

- افتح `/admin.html` وسجل الدخول.
- ارفع تقييمًا تجريبيًا، وتأكد أنه لا يظهر في الموقع قبل الموافقة.
- وافق عليه من تبويب Guest reviews.
- ارفع صورة صغيرة من Photo gallery وتأكد أنها تظهر بعد Refresh.
- اضغط صورة من الرئيسية وجرب التكبير والتنقل.
- افتح الموقع في نافذة خاصة ووافق على Visitor log، ثم راجع ظهور الزيارة في Visitor book.
- افتح متصفحًا آخر وارفض التتبع وتأكد من عدم إضافة سجل.
- من Privacy choices اسحب الموافقة وتأكد من حذف السجلات المرتبطة بالمتصفح.
- راجع Neon storage usage واحتفظ بنسخة احتياطية دورية.

## حدود الخطة المجانية

Render Free يوقف الخدمة بعد 15 دقيقة خمول، وأول طلب بعد ذلك قد يستغرق حوالي دقيقة لإعادة التشغيل. Neon Free يوقف compute بعد 5 دقائق خمول. Render Free Postgres لا يُستخدم هنا لأنه ينتهي بعد 30 يومًا. راجع الحدود والاستهلاك دوريًا.
